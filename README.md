# Pax

> [!CAUTION]
> **DO NOT USE THIS MODULE... YET**
> 
> This module is under heavy development, and is not ready for anyone to use it yet. It is poorly documented, poorly
> tested, and in a heavy state of change. Nothing is being gracefully deprecated or even documented when it changes,
> until the API stabilizes.

Pax (Phoenix Admin eXtensions) is a toolkit for adding CRUD functionality to LiveViews, as well as
an admin interface built on those tools.

## Installation

Rough instructions for now.

### Dependency

Add `pax` to your list of dependencies in "mix.exs":

```elixir
def deps do
  [
    {:pax, "~> 0.0.1-dev.20251023"}
  ]
end
```

### Static assets

Pax ships with a small set of static assets for `Pax.Interface`s:

- "pax.css": basic styles to get you started quickly with a consistent look and feel. This only gives a bare-minimum
  of styling that is designed to be a good starting point for your own customizations.
- "pax.js": JavaScript, such as LiveView hooks, that Pax components need.

These are only needed if you're using `Pax.Interface` directly, and not needed if you are only using `Pax.Admin`, since
it uses its own assets.

There are two ways to include them:

- **Option A:** Bundle them into your own assets with your existing build tools. This is recommended for most
  projects, including new Phoenix projects.
- **Option B:** Load them as separate files, served by Pax.

All of the examples below assume your main stylesheet is in "assets/css/" and your main JavaScript file is in
"assets/js/", so the paths to Pax are "../../deps/pax/priv/assets/pax.css" and "../../deps/pax/priv/assets/pax.js".
Adjust the paths if your files are elsewhere, or if you're in an umbrella project.

#### Option A: Bundle Pax into your own assets

##### JavaScript

"pax.js" installs its hooks on `window.liveSocket` once the page has loaded, so your main JavaScript file must assign
your LiveSocket to `window.liveSocket`. The "app.js" generated by `mix phx.new` already does this.

Import it in "assets/js/app.js". This works with both esbuild (Phoenix's default JavaScript bundler) and Vite:

```js
import "../../deps/pax/priv/assets/pax.js"

// ...

const liveSocket = new LiveSocket("/live", Socket, {...})
liveSocket.connect()
window.liveSocket = liveSocket
```

With Vite, if the dev server refuses to serve the file because it is outside the allowed paths, add the "deps"
directory to `server.fs.allow` in your "vite.config.js".

##### CSS

The Pax styles need to come *after* any global reset, such as Tailwind's preflight, so they aren't reset themselves,
and *before* your own styles and any CSS framework, so that anything that comes after can override them. How to do
that depends on whether your CSS uses cascade layers, and on your build tool.

###### Layered CSS, such as Tailwind 4

In CSS with cascade layers, any styles outside of a layer take precedence over all styles in a layer, regardless of the
order they're loaded in. So Pax must be imported into a named layer with
`@import "../../deps/pax/priv/assets/pax.css" layer(layer_name);`.

Tailwind 4 puts all of its reset styles in the `base` layer, so the Pax styles should be imported into the same layer,
but after the Tailwind preflight styles. For example, in your "assets/css/app.css":

```css
@import "tailwindcss" source(none);
/* Import the Pax CSS into the same layer as the preflight CSS, but after so it takes precedence */
@import "../../deps/pax/priv/assets/pax.css" layer(base);
```

If you use something else with layers, you might need to change which layer the Pax CSS is imported into.

###### Non-layered CSS with esbuild

esbuild bundles CSS that is imported from JavaScript. Import Pax before your own CSS in "assets/js/app.js":

```js
import "../../deps/pax/priv/assets/pax.css"
import "../css/app.css"
```

esbuild writes the combined CSS next to the JS bundle, such as "priv/static/assets/js/app.css". Make sure that is the
file your root layout links to.

###### Non-layered CSS with Vite

Vite inlines `@import` in CSS files automatically, so add this at the top of your main CSS file:

```css
@import "../../deps/pax/priv/assets/pax.css";
```

You can also import it from JavaScript, before your own CSS, like the esbuild example above. The same
`server.fs.allow` note as for the JavaScript applies.

###### Non-layered CSS with Sass

Use `@use`, not `@import`. Sass leaves `@import` of a ".css" file as a plain CSS `@import` that the browser would try
to load at runtime, instead of including the file in your bundle. `@use` must come before any other rules:

```scss
@use "../../deps/pax/priv/assets/pax";
```

If you would rather not use relative paths, add the "deps" directory as a load path, such as `--load-path=../deps` in
your `dart_sass` config, and use `@use "pax/priv/assets/pax";` instead.

###### Non-layered CSS with PostCSS

PostCSS does not resolve `@import` on its own. Install
[postcss-import](https://github.com/postcss/postcss-import) and make it the first plugin in "postcss.config.js":

```js
module.exports = {
  plugins: [
    require("postcss-import"),
    // ...your other plugins
  ],
}
```

Then add the import at the top of your main CSS file, before any other rules:

```css
@import "../../deps/pax/priv/assets/pax.css";
```

###### Tailwind 3 and earlier

The Tailwind CLI includes postcss-import, so no extra setup is needed. If you run Tailwind as a PostCSS plugin instead,
set up postcss-import as described above, before the `tailwindcss` plugin. Import Pax after Tailwind's base styles, so
Pax overrides the preflight resets, but before the components and utilities, so they override Pax. Imports must come
before any other rules, so use the `@import` form of the Tailwind directives:

```css
@import "tailwindcss/base";
@import "../../deps/pax/priv/assets/pax.css";
@import "tailwindcss/components";
@import "tailwindcss/utilities";
```

#### Option B: Load Pax assets as separate files

Use this if you don't have a build system, or can't bundle the Pax assets with it. Since the styles are loaded
separately, they are not in a cascade layer, so any layered styles in your own CSS, such as all of Tailwind 4, will not
be able to override them.

Add the following to your "lib/myapp_web/endpoint.ex", after any `socket` lines, and before `plug Plug.Parsers`. The
best place is right after any existing `plug Plug.Static` lines.

```elixir
plug Pax.Assets
```

Add the Pax assets to "lib/myapp_web/components/layouts/root.html.heex", in the `<head>`, and before your own CSS and
JavaScript, so your CSS can override the Pax styles. As with Option A, your JavaScript must assign your LiveSocket to
`window.liveSocket`:

```heex
<head>
  ...
  <Pax.Components.assets />
  ...
</head>
```
